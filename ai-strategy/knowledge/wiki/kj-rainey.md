## Core ideas

1. **The one goal of working with AI:** "Give AI the exact inputs it needs to get the exact outputs you want. No more, no less." Everything else in his system serves this.
2. **AI is autocomplete on steroids, not a magic genie.** It's a guessing machine: your words → its guess at your meaning → its guess at your desired output. The skill of AI is *helping it guess better* via context. Too little context = vague slop; too much = diluted, token-wasting confusion (his "walking my lizard" story).
3. **Math ↔ Art slider.** AI is great at anything with a verifiable right answer (research, summarization, pattern recognition, sorting volume, repeat tasks, rough drafts, objective coding) and bad at anything subjective/experiential (creative writing, taste, fresh ideas, things meant to be *felt*). Don't rate a macro task ("is AI good at thumbnails?") — **break it into subtasks and rate each one** on the slider.
4. **AI is built on averages, so it can't be truly creative.** "How can AI truly think outside the box when it is the dang box?" Everyone uses the same model, so raw AI output = average by definition. Better contexting moves you along the curve, but it maxes out — past that wall you must inject *human taste*. AI slop will always become the new slop as trends move (iPhone-1 comparison-value argument).
5. **Value = opportunity cost.** AI's true value isn't what it can do, it's what it takes off your plate so you can do the taste-work that matters (his hand-made "mural boards" are the deliberate un-automated part of his videos).
6. **Human-in-the-loop is non-negotiable.** Output-fed-back-as-input loops "slop into oblivion." He distrusts fully autonomous agent loops; the human fixes trajectory.
7. **AI lacks God-given agency and creativity.** Humans are made in the image of a creator God; AI is "a blob of all previous humans' data." It replaces the black-and-white work so you can work "in full color."
8. **Systems thinking is mandatory in the AI era.** A system = inputs → process → output, inside an environment, with feedback (lasagna/kitchen example; his YouTube pipeline; Tesla). Processes are just smaller systems chained together.
9. **Three forms of leverage:** labor (energy × skill × their leverage), **copies** (the big one — code, content, models; massive 0→1 input cost, near-zero distribution cost), and money (buys future labor/copies). Chick-fil-A as the everything-leveraged case study ($22B on one dialed output). AI = "code 2.0," a weird hybrid of copies + labor leverage because it reasons.
10. **Output over process — never scale a system that doesn't work.** Get the desired output manually first ("achieve the desired outcome by any means possible"), *then* add AI leverage. Phases: 0 system doesn't work → 1 works but takes lots of my effort → 2/3 add leverage to cut input → 4 scale with money. "Don't cope with a cool assembly line — people care about the car."
11. **Build heuristic (what to build):** *"Is it valuable enough to me that even if no one else buys or uses it, it was still worth the input to create it?"* Forces low upfront cost, self-use validation (if you don't use it after a week, it's trash), and skill-gain justification. "When you only make stuff that you would actually use, other people use it too."
12. **The real leverage of AI = the creative application of average reasoning at scale.** Like McDonald's systematizing burgers so high-schoolers can run it. Steve Jobs example: same engineers, different vision → wildly different value. 95% of people ask *how* to build; the alpha is in *what* to build.
13. **Context = files + folders.** Two kinds: **context clues** (what you mean) and **instructions** (how to do it — skills are "just text instructions"). Folder structuring is the key skill: his 250-page-PDF → testimonials-folder story; the four levels from scrambled pages to labeled filing cabinets + directions.
14. **CLAUDE.md = the 50 First Dates tape.** A saved starting prompt that orients each fresh Claude instance. Not long-term memory. Prune ruthlessly: if a line isn't needed for *every* prompt, move it to a separate referenced file. ~1 page even for a whole application.
15. **Three Claude roles:** **Builder** (best model, macro context via CLAUDE.md, fresh chat per subsystem or at ~50-75% context, handoff prompts + daily journal logs as short-term memory), **Research/VA** (cheaper model, no standing context, runs in Obsidian/Claudian or Claude Code — curates context so the builder stays clean), **Crash-dummy** (fresh chat, cheaper model, zero context — tests plugins/skills exactly as a user would; notes flow back to the builder). "If you can't make one Claude make you money, you can't make five Claudes make you money."
16. **Three complexity levels of automations** (driven by what you build, not your skill): L1 = folder + CLAUDE.md, interview, run it (fast, but hard to iterate); L2 = full template in Obsidian, serious pre-build context, one solid iteration — for things your team/audience will use; L3 = months-long, journal-driven, ruthless pruning/iteration — plugins and real applications. L3 systems are just L2 subsystems combined. You graduate L2 → L3, never start at L3.
17. **Productizing path: automation → plugin → application.** Iterate heavily *locally* (files + Claude + HTML outputs) until the value prop is dialed; package as a plugin so others can test without UI; only build an application (UI, billing, safety) once people genuinely *use* it, not just test it. Never charge until it's safe.
18. **Workspace = visibility.** IDEs/file-viewers (he prefers Obsidian + Claudian/terminal Claude Code) exist so you can *see* what Claude is doing and fix context. Cowork-style apps hide the files, which caps you at average. Duplicate his template folder per project; journal logs give new instances memory ("read day two, let's continue").
